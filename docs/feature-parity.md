# Feature comparison

Current release: **0.4.0-beta.1**. The core configuration evidence below was established through earlier releases; older version numbers describe historical changes, not the current download.

This comparison covers the feature groups in the approved design. **Implemented** describes actual code/interface behavior; **simulation** means tests with synthetic data; **hardware evidence** includes only procedures that were performed.

Sources: the [LEOBOG tool](https://leobog.driveall.cn/), observed on 2026-10-22; hashed excerpts in the [source fixture](../tests/fixtures/source/a80rt-manufacturer.json); [RT evidence](rt-source-evidence.md); [four-byte binding evidence](binding-source-evidence.md). [Protocol facts](../dist/device/protocol-facts.json) records offsets, commands, and limits. Linked historical evidence documents may be in Vietnamese.

## Write policy and evidence boundaries

On the qualified wired U/firmware 1.37, mapped commands 33/34/35/36/37/39/40 and control 0 use strict header validation, no retries, and changed-field readback. Fn command 38 is blocked before transmission without removing local Fn reading/editing/profiles. ConfigSession checks every draft command before the first write/control, so mixed profiles cannot write some blocks before reaching a known unsupported Fn operation. Source field capabilities describe staging support, not live-write authority.

The Oct 25 native run used production codec source `9697747`: ten cases passed target readback and byte-for-byte restoration of all nine blocks across 6,036 frames. The [summary fixture](../tests/fixtures/a80rt-wired-feature-qualification.json) contains ACK 0/33/34/35/37/39/40, including settings length 32, lighting length 16, and first/final long-block headers. Earlier color 36/control 0 measurements remain separate. Fixtures contain no private raw configuration, macros, or tokens and grant no live attestation. Hosted browser evidence for W color on Oct 23 and RT press/top dead zone/base W on Oct 24 retains its own limited scope.

Not measured: browser Apply for the ten newer native cases, key output/gameplay (apart from the user's negative Fn+U check), timing, visible LEDs, power-cycle persistence, full-profile Apply, maintenance, dongle, or other model/firmware combinations. The negative Fn result does not establish whether firmware or driver is responsible and must not be generalized. Calibration/reset/flashing remain blocked. See the [README](../README.md).

## Historical correctness changes

### 0.3.5

Deselecting a macro through a placeholder, empty, or invalid selection detaches its source and stops recording while retaining the timeline and unsaved field values. Delete/Assign requires a real macro selection. Save creates a new macro, preserving the old macro/references; reselecting a source restores operations on that source. This was a local editor correction with no new hardware measurement.

Four additional regressions were addressed:

- RT validation failures retain input only in the matching context; layer, binding, and selection follow the model.
- Macro ownership is private to the baseline. Fragmented allocations can be rebuilt while preserving opaque/reserved bytes and flags.
- DKS projection obtains ownership only from editable references, protects Fn F1–F12/nonphysical slots, and atomically rejects conflicting shared patterns.
- JSON v1/profile imports check generation before installing results or displaying errors. `app-context-regressions.test.mjs` controls completion order synthetically; it is not a real browser file-race reproduction.

See the [historical design](0.3.5-correctness.md).

### 0.3.4

Missing/replaced macro sources after Revert/profile loading preserve unsaved timelines, stop recording, and require save/reselection before assignment. DKS explicitly supports usage 0, rejects an unselected field, retains default usage 4, and does not enable usage 0 for MT/TGL. Catalog/render evidence established local A80RT 80A2 whole/switch/dead-zone support; live writes remained limited to measured U 80A1/firmware 1.37. Offline profiles preserve raw/opaque baselines without live provenance; transfers into an active session still validate semantics and locked Fn fields.

### 0.3.3

Profiles can restore stored raw-zero actuation after a positive edit. Codec/session transfer accepts the stored value while manual input remains at least 0.01 mm. Synthetic tests verify that preview does not change the draft, failed transactions preserve all blocks, only two actuation bytes are owned, and the qualified wired simulation applies 1.2 mm→raw zero with readback. Raw-zero physical meaning remains unknown. This is neither new USB evidence nor a full-profile browser Apply measurement.
